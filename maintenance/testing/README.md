# Disposable MariaDB migration tests

This directory is test infrastructure, not a production migration runner.
`mariadb_phase2_baseline.sql` recreates only the two application tables needed
for Phase 2 and Phase 5 integration tests. It never imports the historical rows
from `GetNewsAPI/crypto_news_db.sql`.

The repository dump was generated by phpMyAdmin 5.2.1 from MariaDB 10.4.32 on
2025-04-15. It is the newest checked-in dump, contains article data, and predates
the current identity, scheduling, selection, and SEO columns. The test baseline
retains its table types, InnoDB engine, collation, primary keys, and unique URL
keys, then adds only fields required by current committed SQL before Phase 2.

The integration module is opt-in. With the disposable container listening on
`127.0.0.1:13307`, run:

```powershell
$env:RUN_MARIADB_INTEGRATION = "true"
python -m unittest GetNewsAPI.tests.integration.test_mariadb_durable_state
```

Optional `MARIADB_TEST_HOST`, `MARIADB_TEST_PORT`, `MARIADB_TEST_DATABASE`,
`MARIADB_TEST_USER`, and `MARIADB_TEST_PASSWORD` variables override the local
test defaults. `MARIADB_TEST_VERSION_PREFIX` defaults to `10.4.` and supports an
explicit compatibility pass on another disposable MariaDB version. The module
refuses non-loopback hosts and database names that do not end in `_test`.

Local compatibility evidence does not approve production data. Production
still requires its own version/schema checks, preflights, backup verification,
and scheduler/deployment review.
